# 自动精灵无游戏副作用能力核验 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本任务涉及同一台手机的串行 UI 操作，推荐由当前执行者顺序实施，禁止多个执行者同时控制手机。

**Goal:** 在不启动游戏、不进入对局、不动游戏物品的前提下，用新建沙盒核验自动精灵的原生格式、调度、变量、识别和停止能力，为正式脚本提供真实接口依据。

**Architecture:** 只使用自动精灵原生编辑器建立独立沙盒，QtScrcpy 用于观察和操作。每个样例有唯一名称、有限执行范围与明确结果证据；未通过的能力阻止其依赖功能进入游戏阶段，不用虚构接口补齐。

**Tech Stack:** 已安装的自动精灵、QtScrcpy；本地 Markdown 记录；用户提供导出文件后按真实格式只读检查，不安装新依赖。

**Spec:** /Users/hamgua/Downloads/三角洲跑刀自动化_详细设计_2026-10-16.md；/Users/hamgua/Downloads/三角洲跑刀自动化_本地契约与采集清单_2026-10-16.md。

## Global Constraints

- 当前授权只确认需求和流程边界；创建／运行沙盒要等用户确认本计划。对局、购买、补给和系统权限变更不在此授权范围。
- 所有首次选择属于一次游戏会话的初始化；本计划不实际执行这些游戏步骤。
- 不读取或执行加密参考动作，不改现有脚本，不自动删除任何文件。
- 首版一局一停；无匹配、多匹配、未知状态、结果不明的副作用均不猜测继续。
- 不建立 Web API、数据库、云服务，不上传账号或截图。
- 任何游戏触控与对局验证都必须在后续单独获得范围许可。
- 仅使用工具支持的 UI 操作；不绕过授权改用其他控制途径。

## Review Focus

1. 同名沙盒已经存在：换唯一名称，不能覆盖用户脚本（Task 1，V01）。
2. 子脚本未返回或变量不共享：不能把父脚本继续或旧值当成有效结果（Task 2，V03/V04）。
3. 用户中途停止：子和父均不再出现后续动作，不能由返回路径复活（Task 3，V07）。
4. OCR 输出落在剪贴板而非变量：记录真实形式，不能虚构可读变量接口（Task 4，V06）。
5. 导出格式与示例不同／含加密：保留原件，不能按已知文件头伪造新脚本（Task 5，V08）。

## Task 1：确认版本与安全沙盒（V01/V02）

**Files:** 手机新样例 ZZ_DF_SANDBOX_BASIC（唯一名）；实施后新建 CAPABILITY_RESULTS.md。

**Interfaces:** 输入为当前原生 UI 和用户批准；输出为实际自动精灵版本、动作配置字段、唯一名称与固定提示顺序的证据。

- [ ] 打开自动精灵版本信息及本地脚本列表，记录真实版本；查找拟议名称是否已存在，不改现有脚本。
- [ ] 在结果记录登记 V01/V02 为 planned，写明来源和预期：一个新样例仅显示固定 BEGIN、END 标记，无应用启动、触控、无限循环或外部链接。
- [ ] 通过原生编辑器建立唯一名称样例；字段不符合预期时停在配置界面记录，不猜导出字段。
- [ ] 只运行该样例一次，记录实际提示与执行次序。V02 只有证据成立才改 verified；未运行则保持 implemented。
- [ ] 再运行一次核验状态不会沿用旧结果；确认重名时原样例未被覆盖。这是手工 UI 验证，不以 pytest 或 lint 输出冒充。

## Task 2：父子调用、参数与边界（V03/V04）

**Files:** 手机唯一父／子样例；更新 CAPABILITY_RESULTS.md。

**Interfaces:** 消费 Task 1 已确认的提示动作；输出实际调用返回选项、父前／子／父后顺序，以及参数与变量作用域记录。不承诺任意 JS 返回值。

- [ ] 登记 V03/V04 的预期：父先显示 PARENT_BEGIN，再调用有限子样例 CHILD，选中执行后返回主控，最后显示 PARENT_END。
- [ ] 先记录未配置调用时的缺失能力，不运行不完整样例；再用原生“运行脚本”动作配置调用。观察子样例结束之前父后续标记不得出现。
- [ ] 用不同运行次数的唯一固定标记重复执行，区分本次与上次结果。仅在沙盒中取消返回选项做负对照，并记录真实语义，不能套用猜测。
- [ ] 在已确认字段中尝试传入固定沙盒值，并分别观察父／子可见值；未传和未知值是独立负对照。无可用数据通道则记录“不支持”，暂停跨脚本自动决策设计。
- [ ] 逐项记录实际结果与失败原因，不能用“子样例跑过”覆盖 V03 和 V04 两行。

## Task 3：全局停止与诊断门槛（V07/V09/V10）

**Files:** 手机唯一 ZZ_DF_SANDBOX_STOP；更新结果记录；必要截图。

**Interfaces:** 消费 Task 2 的有限串行调用；输出父子停止行为、停止后重跑状态、日志真实形式及触控能力的 verified 或未验证状态。

- [ ] 登记 V07 预期：有限等待前后有不同标记；在等待中使用原生停止，停止后父后与子后标记均不得出现。只用有限无触控等待，不用无限循环模拟。
- [ ] 建立并运行样例，中途停止，核对停止后的界面和有限等待期限。未出现后续标记必须有观察范围记录，不能仅截一帧就判定。
- [ ] 单独重新开始样例，确认上次停止不遗留可误用的结果；停止传播不成立则 F2/F4 不通过，禁止游戏动作。
- [ ] 记录原生是否能实际本地保存诊断；只有真实保存与重新读取的证据才能确认持久化（V09）。不强杀用户应用制造故障，需额外权限或损失的实验标 deferred 并记录触发条件。

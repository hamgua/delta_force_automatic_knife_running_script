# 三角洲行动 · 单人全自动跑刀 · 自动精灵脚本包

功能对标《三角洲免费全自动跑刀双排组队版.zjs》的**单人版**：
云手机 720×1280 上自动排队进烽火地带（零号大坝）、按所选路线（6 条可选，
默认 W3）扫荡房卡房/高价值点位、撤离结算、快速过局（自雷），无限循环。

路线数据来源（均已写入 `点位路线清单.md`）：
- 飞书文档《北七速撤流跑刀焚决》：6 条线路图（红=常规/橙=贪吃/黄=逃生）+ 房卡情报
- 官方地图工具 df.qq.com：14 出生点、10 撤离点（含撤离条件）、16 房卡房/密码房、370 物资点

与参考包最大的区别：**所有动作明文可见、可自行修改**（参考包全部动作加密，
无法审计）。代价是：**点位路线和图像模板必须你自己录制/截取**（它们绑定你
的屏幕和当前游戏 UI，任何人无法替你生成）。

## 一、文件清单

| 文件 | 作用 |
|---|---|
| `脚本_跑刀主控.js` | ★ 主控脚本，粘进自动精灵的「JS 代码脚本」。状态机：大厅→排队→扫荡→撤离→过局→下一局，含自雷、弹窗、确认战斗、死亡恢复、逃生路线、休息、随机抖动、**颜色快路径/标定自学习**（见第八节） |
| `点位路线清单.md` | 6 条路线（E1-E3/W1-W3）明细 + 房卡/撤离点/物资点官方数据对勘 + 录制顺序 |
| `tools/zjs2points.py` | 把你录制的点位 `.zjs` 批量转成 JS 路线数据（坐标自动归一成百分比） |
| `示例_测试点击.zjs` | 最小原生 .zjs 样例，验证你 App 版本能正常导入/执行 .zjs |
| `README.md` | 本文件 |

## 二、安装

1. 云手机装好《三角洲行动》+ 自动精灵（zdjl.site），分辨率设 **720×1280**，
   开启自动精灵无障碍权限；游戏画质/分辨率设置固定下来，**之后不要再改**
   （图像模板和 UI 位置会漂移）。
2. 把 `示例_测试点击.zjs` 传到云手机 `[存储]/自动精灵/` 目录（QQ 传文件即可），
   打开 App 确认能看到并运行——动作生效说明导入链路 OK。
3. 自动精灵里新建 **JS 代码脚本**，把 `脚本_跑刀主控.js` 全文粘贴进去保存。

## 三、工作流（一次性配置）

```
① 选路线             CFG.route = 'W3'（推荐首发; 其他 E1/E2/E3/W1/W2
                      按出生点位置选, 见 点位路线清单.md 5.2 节）
② 检查房卡          战备界面确认背包带齐本路线房卡（见清单 5.3 节）
③ 手动熟悉路线       在云手机上按文档红箭头把整条线完整跑 1 遍
④ 录制路线段          自动精灵「录制」, 按清单 5.4 节顺序逐段录（W3=4 段+逃生 1 段）
⑤ 转换路线           python3 tools/zjs2points.py 01_*.zjs … --extract 04_撤离.zjs
                     → 生成 点位路线_生成.js, 把各段 steps 粘进 ROUTES 对应 points[n].steps
⑥ 设置图像变量       App「变量-图像」里按第四节清单建 img_* 变量
⑦ selfTest()        切到大厅画面, JS 脚本里先注释掉 main()、运行 selfTest(),
                     核对大厅相关图像; 弹窗末尾附「快路径/标定状态」报告
⑧ 单局测试            CFG.rounds=1, 跑 main(), 全程盯着云手机看。
                      注意: 第 1 局是纯找图(自学习), 速度=旧版; 第 2 局起
                      自动切快路径(定点点击+颜色指纹), 明显变快属正常
⑨ 放开跑              没问题后 CFG.rounds=0, 配合 restEvery/restMs 休息机制
```

## 四、图像变量清单（App「变量-图像」逐个创建）

> 截取原则：截**按钮/图标/静态地标**本身，裁掉动态文字（倒计时、血量、
> 随机物品名）。区域尽量小。变量名必须与下表完全一致。

| 变量名 | 截什么 | 出现时机 | 重要度 |
|---|---|---|---|
| `img_lobby` | 大厅独有标志（如烽火地带入口） | 大厅 | ★★★ 缺失会卡死 |
| `img_mode_entry` | 大厅「烽火地带」入口按钮 | 大厅 | ★★★ |
| `img_map_select` | 选图界面「零号大坝」卡片 | 选图 | ★★★ |
| `img_start` | 「开始/快速开始」按钮 | 战备确认界面 | ★★★ |
| `img_inmatch` | 对局内独有 UI（小地图框/任务栏角标） | 对局内 | ★★★ |
| `img_die` | 「撤离失败」或死亡字样 | 死亡时 | ★★★ |
| `img_settle_next` | 结算界面「下一局/返回大厅」按钮 | 结算 | ★★★ |
| `img_spawn` | 出生/索降完成后的标志（可省，脚本有 inmatch 兜底） | 进场 | ★★ |
| `img_battle` | 「确认战斗」弹窗按钮 | 遇敌/弹窗时 | ★★ |
| `img_grenade` | 武器栏手雷图标（捡到手雷后才有） | 对局内 | ★★（自雷用，可缺） |
| `img_extract` | 撤离点交互按钮/标记 | 撤离点 | ★★★ |
| `img_popup_close` | 公告/活动/客服弹窗的 X | 任意 | ★★ |
| `img_pause` / `img_pause_exit` | 暂停按钮 / 暂停菜单「退出对局」 | 卡死恢复用 | ★★ |
| `img_gear_knife` | 战备界面状态标志（固定空装可不用） | 战备界面 | ★ |
| `img_danger` | 危险信号（如小地图上密集红点/遇敌标记） | 对局内 | ☆ 可选，未设则逃生线不自动触发 |
| `img_queuing` / `img_safebox_ok` | 可选，脚本不强依赖 | — | ☆ |

## 五、参数速查（`脚本_跑刀主控.js` 顶部 CFG）

| 参数 | 默认 | 说明 |
|---|---|---|
| `route` | W3 | 路线选择 E1/E2/E3/W1/W2/W3（非法值回退 W3） |
| `escapeOnDanger` | true | 检测到 img_danger 时走本路线逃生线（未录制则仅日志提示） |
| `logCards` | true | 开局日志列出本路线要收的房卡 |
| `rounds` | 1 | 局数，0=无限。先 1 测试！ |
| `restEvery` / `restMs` | 15 局 / 20 分钟 | 休息节奏，**建议保留** |
| `sim` | 78 | 找图相似度；误识别调高(85+)，找不到调低(70) |
| `jitter` | 12 | 点击随机偏移 px；越风控可加大 |
| `actionGap` | 120–420ms | 动作间隔；越慢越像人 |
| `selfKill` | true | 卡死 15s 后自动自雷结束对局 |
| `watchEvery` | 10 | 每 N 步做一次全局状态检查（配合快路径 10~12 足够，别调太低） |
| `useFastState` | true | 颜色快路径总开关；关掉=旧纯找图行为 |
| `colorTol` | 45 | 颜色指纹容差(0-100)：快路径误判→调低(30~35)；不命中→调高(55~60) |
| `calibKey` | kd_calib | 标定数据存储键；游戏大更新后清掉重来（见第八节） |

## 六、排错

| 现象 | 处理 |
|---|---|
| 启动报「图像变量未设置」 | 按第四节建变量；变量名一个字符都不能差 |
| selfTest 大量「未找到」 | 确认当前画面是该图像出现的时机；重截更清晰的图；调低 sim |
| 点不中/位置偏 | 云手机分辨率不是 720×1280 → 改 CFG.screenW/H；或录制时和运行分辨率不一致 |
| 排队很久没进局 | 查云手机网络；`queueTimeoutMs` 可调 |
| 中途卡住不动 | 看 `kd_log`（脚本日志）；确认 `selfKill` 开着；手动切到云手机看画面 |
| 快路径误判状态（对局内突然去过局流程） | `colorTol` 调低到 30~35；仍不行则 `useFastState:false` 回退纯找图 |
| 第 2 局起没变快（快路径没生效） | selfTest 看「快路径/标定状态」：颜色API 不可用=App 版本无 getScreenColor（自动降级纯找图，属正常）；指纹数=0=第 1 局没跑完整 |
| 游戏更新后全乱 | 游戏 UI 改了 → 重截全部图像变量、重录路线（参考包也一样会失效）；同时清标定: JS 脚本里跑一次 `zdjl.removeStorage('kd_calib')`，再跑一局自动重建（或跑 `calibrate()`） |
| 闪退 | 找图区域太大/相似度太高导致性能问题：缩小 `IMG_AREA`、用 `quickSearch` |

## 七、风险与合规（务必读）

1. **封号风险**：这是游戏自动化脚本，违反《三角洲行动》用户协议，腾讯天盾
   会对云手机、固定轨迹、高频操作做风控。内置的随机抖动/间隔/休息只能降低
   概率，**不能消除**。请用小号测试，重要账号不要上。
2. **收益风险**：零号大坝是竞争最激烈的图，跑刀收益随赛季/在线人数波动，
   脚本扫的是固定爆点，人多了就是陪跑。
3. **隐私**：本包不联网、不上传任何数据（主控 JS 里没有任何 requestUrl 调用，
   可自行审计）。不要运行来路不明的加密脚本包（参考包那种）——加密动作不可审计。
4. 录制/转换工具只在你本地和云手机上处理文件，不上传。

## 八、进阶

### 8.1 颜色快路径与标定自学习（为什么第 2 局开始变快）

旧版每个判断都是「整屏截图 + 模板匹配」(每次 200~500ms)。新版改为**便宜手段优先、
找图只做兜底**的混合模式，**零手工标定，自动学习**：

1. **按钮定点点击**：每次 `findImg` 成功，自动把命中坐标存入标定表
   (`kd_calib`)。之后同一按钮（开始/下一局/手雷槽/烽火地带入口等固定位置）
   直接 `click(x,y)`，零截图零匹配，未标定时才回退找图。
2. **状态颜色指纹**：大厅/对局内/死亡/结算 各界面在 10 个固定采样点
   （四角+边缘，避开中央动态内容）记一组颜色。运行时 `getScreenColor`
   单点取色（~ms 级）与指纹比平均距离，判定当前界面，代替整屏找图。
3. **自学习时机**：第 1 局找图命中时顺带采样学习（死亡屏指纹在实际死亡时
   自动补学；死亡屏与结算屏都有「下一局」按钮，脚本会用「死亡字样缺席」
   校验，不会把死亡屏颜色误学成结算指纹）。第 2 局起全程快路径。
4. **安全机制**：快路径判定死亡/掉出对局前会二次采样确认（`confirmState`），
   防颜色漂移造成对局内误点；App 版本无 `getScreenColor` 时自动降级纯找图，
   行为与旧版完全一致；`CFG.useFastState=false` 可强制关快路径。
5. **手动标定向导（可选）**：不想等自学习时，注释掉 `main()` 跑 `calibrate()`，
   按向导逐步切到 大厅→战备→对局内→结算→死亡 各界面采样（每步可跳过）。
   `selfTest()` 弹窗末尾附「快路径/标定状态」报告（API 可用性/已学项/当前判定）。
6. **失效重建**：游戏大更新/换分辨率/改画质后 → `zdjl.removeStorage('kd_calib')`
   清掉标定，重跑一局自动重建；或跑 `calibrate()` 重新标定。

### 8.2 路线与点位

- 路线里混用 `{i:'img_xxx'}`（找图点击）比纯坐标稳得多：每局出生/刷新的位置
  固定（固定爆点），但 UI 浮层（背包栏遮挡等）会变，找图能自适应。
- 想加新点位：录一段 .zjs → 转换 → 往 `ROUTES[路线].points` 里插一行即可，顺序即路线；
  新路线照 `ROUTES` 现有结构（name/spawn/points/extract/greedyNote/escape）加一个键。
- 双人版思路（参考包的"组队版"）：两台云手机各跑本脚本，把 POINTS 表拆成
  互不重叠的两半（东/西各半），再在各自脚本里加一个"等队友"的等待步骤即可；
  但双人操作时间差被游戏内表现为"双人开图"，风控关注度更高，慎用。
